Hướng dẫn Run/Debug Full Project

File này tổng hợp cách dùng bộ shared run configurations trong thư mục .run/ cho repo thingsboard. Mục tiêu là chạy nhanh theo 2 mode: monolith local và microservices local.

Java 17 Maven PostgreSQL Kafka ZooKeeper Redis/Valkey

1. Các File Đã Có

Note quan trọng: embedded UI vẫn bật mặc định. Bạn không cần sửa application/pom.xml để quay lại mode đầy đủ UI. Chỉ các config có chữ Backend Only hoặc No UI mới chủ động tắt serve UI hay loại ui-ngx khỏi runtime/package.

Các shared run configs đã được thêm sẵn trong .run/:

TB - Install DB (monolith demo)
Khởi tạo schema PostgreSQL và nạp demo data.
TB - Monolith Local
Chạy toàn bộ backend trong một process.
TB - Core
Chạy tb-core mode microservices.
TB - Rule Engine
Chạy tb-rule-engine.
TB - HTTP/MQTT/COAP/LwM2M/SNMP
Các transport services tách riêng.

2. Mở Trong IntelliJ

  1. Mở project root /mnt/ssd-dev/TB-IOT/thingsboard trong IntelliJ IDEA.
  2. Nếu chưa thấy configs, chạy Reload All Maven Projects hoặc mở lại project.
  3. Vào góc trên bên phải của IntelliJ và chọn các cấu hình bắt đầu bằng TB - ....
  4. Dùng nút Run để chạy thường hoặc Debug để debug trực tiếp.

Ưu điểm: các config này dùng MavenRunConfiguration, nên ít bị lỗi do khác tên module IntelliJ giữa các máy.

3. Monolith Local

Đây là mode gọn nhất để debug full backend. Repo hiện mặc định phù hợp với monolith local: queue in-memory, service type monolith, cache caffeine, telemetry SQL.

Bước 1: chạy PostgreSQL

docker run -d --name tb-postgres \
  -e POSTGRES_DB=thingsboard \
  -e POSTGRES_PASSWORD=postgres \
  -p 5432:5432 \
  postgres:16

Bước 2: init database một lần

Trong IntelliJ, chạy config TB - Install DB (monolith demo).

Config này tương đương việc bật Spring profile install và truyền --install.load_demo=true.

Bước 3: chạy backend monolith

Trong IntelliJ, chạy hoặc debug config TB - Monolith Local.

Thông số Giá trị
HTTP http://localhost:8080
DB jdbc:postgresql://localhost:5432/thingsboard
Queue in-memory
Cache caffeine
Service type monolith

Tài khoản mặc định

  • sysadmin@thingsboard.org / sysadmin
  • tenant@thingsboard.org / tenant nếu đã load demo data

4. Microservices Local

Mode này dùng khi bạn cần debug flow đúng theo kiến trúc tách service: tb-core, tb-rule-engine và các transports độc lập.

Infra bắt buộc

  • PostgreSQL trên localhost:5432
  • Kafka trên localhost:9092
  • ZooKeeper trên localhost:2181
  • Redis/Valkey trên localhost:6379

Thứ tự khuyến nghị

  1. Khởi động PostgreSQL.
  2. Nếu DB chưa có schema, chạy trước TB - Install DB (monolith demo) để init schema cơ bản.
  3. Khởi động Kafka, ZooKeeper, Redis/Valkey.
  4. Run TB - Core.
  5. Run TB - Rule Engine.
  6. Run từng transport cần debug.
Run config Port mặc định Vai trò
TB - Core 8080 REST API, auth, entity logic, UI static khi build embedded
TB - Rule Engine 8082 Xử lý rule chains ở mode tách service
TB - HTTP Transport 8081 HTTP device transport
TB - MQTT Transport 1883 / 8883 MQTT transport
TB - COAP Transport 5683 / 5684 CoAP transport
TB - LwM2M Transport 5685 / 5686 / 5687 / 5688 LwM2M transport và bootstrap server
TB - SNMP Transport 1620 và 8083 SNMP transport

Lưu ý: các transport configs được set để chạy theo microservices local, nên sẽ dùng Kafka, ZooKeeper và Redis-compatible cache.

5. UI Dev Local

Nếu bạn muốn debug full stack với hot reload cho Angular UI, backend nên chạy local ở 8080 và UI dev server ở 4200.

Hiện trạng repo

  • ui-ngx/proxy.conf.js đang forward về domain remote.
  • ui-ngx/src/environments/environment.ts đang đặt apiBaseUrl sang domain remote.

Nếu muốn đổi sang local

// ui-ngx/proxy.conf.js
const forwardUrl = "http://localhost:8080";
const wsForwardUrl = "ws://localhost:8080";
// ui-ngx/src/environments/environment.ts
apiBaseUrl: 'http://localhost:8080',
cd ui-ngx
yarn install
yarn start

Sau đó mở http://localhost:4200.

6. Gợi Ý Workflow

Khi sửa backend business logic

  1. Dùng TB - Monolith Local.
  2. Đặt breakpoints trong application, dao, rule-engine.

Khi sửa luồng queue hoặc partitioning

  1. Dùng TB - Core + TB - Rule Engine.
  2. Nếu cần, bật thêm transport cụ thể.

Khi sửa transport protocol

  1. Chạy TB - Core.
  2. Chạy riêng transport đang sửa, ví dụ TB - MQTT Transport.
